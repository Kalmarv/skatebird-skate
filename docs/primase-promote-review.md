# SkateBIRD → primase promotion review

2026-10-19. Static review of SkateBIRD **b3e8c091** (2,133 lines in `program/src/*.rs`, including tests), its scan and supporting tools, against primase **4f69cca2** and PRIMASE-MODEL with clarifications. The program pins **6feaa93f** (`program/Cargo.toml:11`); recommendations below compare with newer main, not just that pin. No repositories changed, builds run, or game evidence collected. Paths beginning `program/` or `tools/` are SkateBIRD; other code paths are primase. Sizes are rough extraction/implementation estimates, not commitments.

**Recommendation:** promote the material preparation first, then separate ambient-light meaning from its approximation, then bring the scan's source facts into the appropriate readers. Keep the recipe in SkateBIRD. Most of `settings.rs` already composes the right library operations; moving it wholesale would reverse the model.

1. **High value: ORM packing as a reusable image pass.** `program/src/pack.rs:20` packs separate PBR occlusion and metallic/roughness images, shares results by image pair, and updates bindings. Move to `toolkit/image/src/orm.rs` as typed `PackOrm` plus registry entry. This is standard PBR/image work, independent of Unity and ReSkate; the subsequent conversion to Studio's channel layout already exists in `worlds/reskate/src/passes/raise/materials.rs:212`. That code deliberately refuses distinct images at line 230, so this fills a real library gap rather than replacing a writer failure with hidden adaptation.

   Program retains the choice to pack, output-size policy (today: match metallic/roughness), and missing-mip policy. Nearest resampling can be a documented implementation default; it need not become a mandatory algorithm question. **Correct before promotion:** sampling compatibility checks at `pack.rs:37` omit transforms; missing AO mips silently become white at line 86, and an invalid AO byte lookup does likewise at line 84. Validate images and sampling first; generate missing mips explicitly or refuse/report, rather than losing occlusion silently. Reuse image channel/level infrastructure (`toolkit/image/src/channels.rs:1`). About **170 production lines + existing 70 test lines**, with focused transform/mip coverage. Direct reuse: Sledding/other Unity exports; GTA/Sekiro whenever they provide separate PBR masks, not a claim their current recipes need it.

2. **High value: variant specialization and single-sampling preparation.** `program/src/variants.rs:7` separates placements using different material variants; `uv_policy.rs:24` makes slots adopt the base texture's transform, then invokes existing `bake_texture_transforms`; `wrap.rs:16` similarly chooses one wrap, including collapsing V to U. Split into `toolkit/meshops`'s `SpecializeMaterialVariants` mechanism and explicit `worlds/reskate/src/passes/` preparation for the destination's single sampling layout. Use the existing transform baker, not another implementation. Program selects base/other anchor, how conflicts are approximated or refused, and whether unused variants are discarded. It can retain today's base-first, UV0, U-wrap choices.

   **Do not copy the current helper wholesale:** `variants.rs:31` strips variants from all unplaced prototypes; specialization alone should not silently select away alternatives. Separate that choice and report it. The specialization also rejects LOD graphs: retain that clear precondition unless deliberately extending support. Promote new entities with declared provenance/ownership for parts (`core/src/convert.rs:264`), not just `spawn` plus `copy_components`.

   **Fix an existing primase defect here:** `toolkit/meshops/src/texcoords.rs:17` enumerates only five mutable slots, although `PbrMaterial::textures()` includes both specular slots (`core/src/pbr.rs:230`). The baker transforms geometry, then clears only those five slots at `texcoords.rs:179`: a specular transform remains and can be applied again or refused downstream. Correct the library's slot traversal; do not compensate by erasing it in the program. Also, `main.rs:542` fills missing UVs *before* specializing, while `formats/gltf/src/prepare.rs:204` checks only default primitive materials. A variant-only sampled set can be missed. Specialize before filling on this route, or extend the shared fill operation to variants. Its generic mechanism could live in meshops with the glTF API re-exported.

   About **200–300 production lines**, plus focused tests for two differently tiled placements, specular transforms, variant-only UVs and unused alternatives. These operate on core representations and benefit GTA/Sekiro/Sledding wherever variants or incompatible slot sampling occur. The lossless specialization belongs in toolkit; ReSkate's choice to sacrifice a slot's sampling belongs in its destination passes.

3. **High value: explicit blended-surface adaptation for ReSkate.** `program/src/cutout.rs:15` converts non-decal, non-water blended PBR materials to a mask at 0.5. Put the destination operation in `worlds/reskate/src/passes/`, before `raise-skate`, as e.g. `PrepareReskateBlendedSurfaces` with stated selection and cutoff. The program chooses whether it applies to all eligible surfaces or selected canopy materials, and supplies 0.5. Keep per-material approximation reporting; glass is not equivalent to foliage merely because both blend.

   This is **not already covered** by `PrepareReskateUvRepeats`: `worlds/reskate/src/passes/uv_repeats.rs:1` adapts only triangles exceeding the repeat limit, after materials are raised. Reuse its relevant destination mechanisms where practical, without conflating the two predicates. This is an explicit workaround for the observed compiled rendering path, not proof that every future ReSkate blend path is incapable of drawing world surfaces. Do not change Unity's faithful alpha reading to implement it. About **50–100 production lines** plus selected/excluded-material tests. Applicable to GTA/Sekiro/Sledding foliage or transparent surfaces when their programs choose the same approximation.

4. **High value, larger design step: ambient facts and ambient-to-light approximation.** `program/src/ambient.rs:28` combines interpretation of Unity ambient settings, a mean-colour approximation, a point-light grid, target-driven calibration assumptions and a surface-clearance search. Unity already reads the stored facts (`worlds/unity/src/components.rs:601`, `read/scene.rs:675`): do not add the grid to the reader.

   Separate a Unity pass interpreting supported ambient modes from a reusable approximation pass. A core ambient representation is justified by the model's “common concept” rule, even with one current reader: define linear colour, directional/flat meaning and units explicitly; do not label a relative Unity intensity as measured illuminance. `core/src/environment.rs:10` currently explicitly defers ambient until that definition exists. Preserve engine-specific modes/data in `unity.render_settings`. The chosen mean-colour reduction must be reported, and skybox/custom modes must not silently fall through to trilight as `ambient.rs:39` currently does.

   Put the grid-generation/clearance mechanism in toolkit (a small lighting module), with a ReSkate preparation pass if its intensity interpretation depends on the destination. Program keeps **15 m** spacing, bounds, clearance **spacing/4**, reach **spacing×1.5**, and the lighting calibration **3.007** (`settings.rs:29`); these determine output, not source truth. Reuse `primase_image::srgb_to_linear_f32` instead of `ambient.rs:15`, and the already-used meshops distance function. The reusable surface index is the new mechanism, not that distance calculation. For parts, use one map-anchored grid and sufficient neighbouring geometry; the current whole-world triangle copy is not a bounded parts implementation.

   About **250–450 production lines** for the split and defined core meaning, plus tests. Immediate other user: Sledding/Unity environments. GTA/Sekiro could use the approximation once their readers supply compatible ambient meaning; do not invent ambient from their punctual lights. Keep the current helper temporarily if the units/representation cannot yet be specified clearly.

5. **Medium value: recover source markers and selection facts from the scan.** The Rust program consumes a saved JSON scan (`main.rs:168`, `level.rs:39`), not the game for these facts. `tools/skatebird_scan.py:349` decodes `ResetPosition.startingPosition`; line 408 identifies mission givers. Those are **SkateBIRD meanings**, not Unity meanings. Add `worlds/skatebird/src/read/` and namespaced components, depending on `worlds/unity`; retain all supported reset/mission points and their state. Use Unity's existing object resolution, hierarchy, collider and lighting readers (`worlds/unity/src/read/scene.rs:314`, `:596`, `:675`, `:722`) instead of porting the Python hierarchy decoder wholesale. The raw offset read at scan line 354 needs a checked, version-specific decoder, not an assumed general MonoBehaviour layout.

   Keep spawn fallback, mission-giver-to-travel mapping, named-landmark heuristics, bounds excluding colliders over **100 m**, and travel sampling/caps in program settings/selection passes (`skatebird_scan.py:385`, `:574`, `:611`, `:647`). They are policies already baked into the snapshot. Expose facts first; do not make those filters reader defaults.

   `program/src/level.rs:132` directly constructs `SkateMarker` and repeats the target conversion. Instead emit selected `core::Marker` + canonical `Transform` before raising: `core/src/marker.rs:15` and `worlds/reskate/src/passes/raise/mod.rs:857` already implement this. This also makes the points available to other destinations. About **150–300 new production lines** for the game decoder/adapter, with the recipe selection remaining outside. SkateBIRD script decoding is not reusable by GTA/Sekiro/Sledding; the marker representation and target conversion already are. No new universal “spawn system” is needed.

6. **Medium value: explicit omission of material-less primitives.** `program/src/unmaterialed.rs:9` is generic selection over Mesh/MaterialVariants. Promote a meshops omission pass (or a thin destination wrapper) with an explicit omit choice; preserve the option to supply a fallback material in a different recipe. Reuse `World::rebuild_primitives` as it already does. Record actual primitive/triangle drops in `PassLog::dropped`, rather than only count strings (`unmaterialed.rs:34`); remove the diagnostic environment variable from the library API. Handle removal of the final primitive with coherent per-primitive components/references. Do not remove collision or source material facts from the Unity reader to avoid a writer refusal. About **70–120 production lines**; potentially useful for any source with incomplete material coverage. No evidence here requires forcing it into every conversion.

7. **Lower priority: reusable later stages and diagnostics, not another conversion framework.** `program/src/compile.rs:24` is a ~60-line Studio invocation wrapper. A library API may live in `worlds/reskate/src/compile/` as a declared later stage, parameterized by executable/game/staging locations and compile choices. Keep `--no-stream`, `--no-lods`, `--no-gi`, noon, output names and orchestration in the program. Similarly extract only reusable ReSkate package-schema/compatibility helpers from `package.rs:12`/`:56` if needed; author/version/description, release ZIP naming, installation and game enabling stay consumer/tool responsibilities. GTA/Sekiro/Sledding can share those stage helpers; there is no need to move ordinary ZIP/directory utilities into core.

   `tools/audit_compiled_materials.py:32` already reuses reskate-tools' readers; keep that inspector with shared ReSkate diagnostics rather than importing its hardcoded paths, private APIs and GPL parser dependencies into primase. `tools/audit_facing.py:30` duplicates a small GLB reader: production Rust diagnostics should use `toolkit/glb/src/container.rs:19`; an independently implemented offline checker can remain separate, with its supported subset stated. `tools/unitypy_census.py:1` is an independent reader oracle, not production reader code: preserve that independence and centralize it with oracle tooling if moving it. Camera/teleport tools, image comparisons, QA reports and `ingame_levels.sh` remain test/consumer tooling. They are not read→pass→write library operations.

**Cross-cutting adoption, not another promoted framework:** `main.rs:412` hand-skips any pass when any required component is absent, does not check resources, and prints “nothing to lower.” Keep explicit recipe branching, but distinguish absent optional input from a partially missing precondition. Current core's per-part opt-in skip is narrower (`core/src/pass.rs:1105`); it is not an automatic substitute for whole-world recipe choices. `main.rs:472` returns on failure before printing the collected report; `show` at line 481 displays only counts and approximations. Retain failed logs and surface omissions/drops as well. Promoted helpers should be typed passes with declarations and structured logs, using existing `PassManager`/conversion reports. Direct composition remains allowed: adopting `convert` is not a requirement.

**Keep as recipe:** `settings.rs:54`, `:81`, `:187` already call library LOD/state selection, Unity lowering, collision tessellation, normal handling, ReSkate tint/texture/water/spawn/overlay/collision/budget preparation. In particular the new vertex-tint route uses `LowerTintReskate` (`settings.rs:195`); it is already promoted. Keep level lists, surface maps, tuned quality values and build concurrency in SkateBIRD. Preserve its glTF/web branch before ReSkate approximations (`main.rs:422`). First extraction checks should exercise the affected material/marker/light behavior and its reports; a new full eight-level game run is not a prerequisite to deciding placement.
